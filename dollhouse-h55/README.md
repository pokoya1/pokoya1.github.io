# 投資ドールハウス H5.5 — 家具・経路・予約の再編集

## 意図
H5の動作素材を引き継ぎ、機能を増やすより「2匹のかわいい生活」を支える制御を安定化させる。H5は変更しない。

## 正本と生成物
- **scene.json**: 家具の位置・描画素材とサイズ・占有領域・スポット・行動・キャラ速度・床・グラフを統合した唯一の編集用正本。窓は家具ではなく固定の背景fixture。
- **src/core.mjs**: DOM非依存のシミュレーション核。現在地から到達可能なウェイポイントを探索、経路が成立してから席を予約、占有と待機キューを検査。
- **src/ui.mjs**: 旧版③ハムスターと暫定ペンギンの表示・UIのみ。
- **build.py**: scene.jsonからHTMLを生成し、正本のSHA-256を埋め込む。**index.htmlとstandalone.htmlは手編集しないこと。**
- **make_scene.py**: H5既存版からの一回限りの移行スクリプト。H5.5運用時には実行せず、scene.jsonを編集する。
- **tests/test.mjs**: 純粋なモデルに対する10件の単体試験。
- **tests/browser_qa.py**: Chromium 2画面幅とJavaScript無効表示の動作試験。
- **tests/verify_build.py**: JSONとHTMLの一致、および素材の実在確認。

## 実行
```bash
node tests/test.mjs
python tests/verify_build.py
python tests/browser_qa.py
python build.py
```
`index.html` は `src/ui.mjs` と画像フォルダーが必要。GitHub Pages用に配置する場合はフォルダ構造をそのまま使用。`standalone.html` は素材とロジックを内包するが、**ChatGPTアプリ内プレビューでJSが実行される保証はない**。そこで静止画 `qa/mobile.png` と `qa/static.png` を別途添付する。

## 制御の仕様
- 初期座標から最近接の「見通し可能な」グラフ節点への接続を検証し、グラフで目的地へルーティングする。現在地→接続点も検査対象。厳密な自由経路探索ではない。
- 移動先で空き席があれば経路確定後に予約する。満席時の手動指示だけFIFOキューで待機し、解放時に繰り上げる。経路不成立なら予約を保持しない。
- ラグは定員2で、席に予約順のスロット座標を割り当てる。
- 自律行動では満席・現在地・直近2スポット・経路不成立を除外。行動後4〜10秒程度滞留する。スポットが無いときは待つ。
- 描画アニメーションは旧版③の素材を維持し、ペンギンは全身画像で仮移動。自然な足運び・表情差分は未完成。

## 既知の不足
1. 家具とキャラクターの前後遮蔽は未実装。`z`は床接地点に基づく単一尺度へ揃えたが、前景専用画像がないため家具の手前奥を完全には表現できない。
2. 経路障害物判定は既存の占有ポリゴンによる近似で、二匹の移動中の接触や、変則的な配置の抜け道までは網羅していない。模様替えUIも未実装。
3. クレイ調家具の投影・床奥行きの精密整合は未完了。
4. 本当にかわいい待機・表情・姿勢差分やニュース連動は次工程。現在の生活演出は位置・記号バッジと時間遷移のみ。
5. iPhone/Android Safari・Chrome実機、長時間の発熱・電池消費、GitHub Pagesでの操作は未検証。

## 判定
**H5.5 の内部制御の再編集試作**。自動テスト通過は実機品質の合格ではない。H6前にHTTPS上の実機テストを実施する。
